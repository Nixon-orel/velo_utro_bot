# Veloutro Bot (Ruby)

Telegram-бот для организации около велосипедных мероприятий, написанный на Ruby.

## Описание

Veloutro Bot позволяет пользователям создавать мероприятия, искать существующие, присоединяться к ним и управлять своими мероприятиями. Бот публикует мероприятия в общий канал, при включённой настройке ежедневно напоминает о событиях на ближайшие 24 часа и использует прогноз погоды для повышения безопасности поездок.

## Технический стек

- **Язык программирования**: Ruby
- **Фреймворк для Telegram**: telegram-bot-ruby
- **База данных**: PostgreSQL
- **ORM**: ActiveRecord
- **Веб-фреймворк**: Sinatra
- **Шаблонизатор**: Mustache
- **Локализация**: I18n
- **HTTP клиент**: Faraday (для WeatherAPI)
- **Планировщик**: Rufus-scheduler

## Установка и запуск

### Предварительные требования

- Ruby 3.2.1
- PostgreSQL
- Telegram Bot Token

### Установка

1. Клонируйте репозиторий:

```bash
git clone git@github.com:Nixon-orel/velo_utro_bot.git
cd velo_utro_bot
```

2. Установите системные зависимости PostgreSQL:

```bash
sudo apt update
sudo apt install libpq-dev postgresql-client postgresql postgresql-contrib
```

3. Установите зависимости Ruby:

```bash
bundle install
```

4. Создайте файл `.env` и заполните его своими данными:

```bash
cp .env.example .env
```

Отредактируйте файл `.env` и укажите свой Telegram Bot Token и другие настройки.

### Запуск

#### Настройка переменных окружения

Актуальный шаблон со всеми поддерживаемыми переменными находится в `.env.example`. Для запуска бота обязателен `TG_TOKEN`; для работы с публикациями также нужен `PUBLIC_CHANNEL_ID`.

**Описание переменных окружения:**

- `TG_TOKEN` - токен Telegram бота (получается от @BotFather)
- `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME` - настройки подключения к PostgreSQL
- `PUBLIC_CHANNEL_ID` - ID публичного канала для публикации мероприятий, ежедневных анонсов, погоды и статистики
- `BOT_USERNAME` - имя пользователя бота без @ (например, VeloutroBot)
- `ADMIN_IDS` - список Telegram ID администраторов через запятую
- `STATIC_EVENTS` - типы статических мероприятий (без скорости/расстояния)
- `DAILY_ANNOUNCEMENT_ENABLED` - включает автоматические ежедневные анонсы (`true`/`false`)
- `DAILY_ANNOUNCEMENT_TIME` - время ежедневного анонса в UTC в формате `HH:MM` (`18:30` соответствует 21:30 по Москве)
- `MONTHLY_STATS_DAY` - день месяца для автоматической отправки статистики (1-28)
- `TIMEZONE` - часовой пояс приложения (по умолчанию Europe/Moscow)
- `WEATHER_API_KEY` - ключ API для WeatherAPI (получить на https://www.weatherapi.com/)
- `WEATHER_ENABLED` - включение функций погоды (true/false)
- `DEFAULT_WEATHER_COORDINATES` - координаты по умолчанию (формат "широта,долгота")
- `DEFAULT_WEATHER_CITY_NAME` - название города по умолчанию
- `WEATHER_ADMIN_ALERTS` - уведомления администраторов о проблемах с погодой (true/false)
- `WEATHER_DEBUG` - включение DEBUG-уровня логов всего приложения в production для диагностики (true/false)

#### Создание базы данных

1. Создайте пользователя PostgreSQL:
```bash
sudo -u postgres -H createuser -s $USER
```

2. Создайте базы данных:
```bash
createdb velo_utro_bot_development
createdb velo_utro_bot_production
```

#### Применение миграций

```bash
bundle exec rake db:migrate
```

#### Запуск бота

```bash
bin/bot
```

Веб-приложение запускается отдельно:

```bash
bin/web
```

`ruby app.rb` оставлен как совместимая точка входа: в development он запускает бота, в production — веб-приложение.

`bin/bot`, `bin/web` и Rake автоматически загружают `.env` через Dotenv. Шаблон `.env.example` не рассчитан на `source` в shell.

После обновления кода всегда применяйте миграции до запуска приложения. Миграция `007` добавляет `events.published_at`, которое заполняется только после успешной отправки сообщения в Telegram. Миграции `008`–`010` добавляют постоянную очередь погодных Telegram-доставок, возрастающую версию погодного расписания события и отметку завершённой сверки доставки с событием.

## Команды бота

### Основные команды
- `/start` - Начало работы с ботом, регистрация пользователя и приветственное сообщение
- `/menu` - Показать главное меню с доступными командами
- `/help` - Получение справки по использованию бота
- `/create` - Создание нового мероприятия
- `/find` - Поиск существующих мероприятий
- `/my_events` - Управление своими мероприятиями (показывает только предстоящие события)

### Подписка на уведомления
- `/subscribe` - Подписаться на уведомления о новых событиях (получать сообщения о всех новых мероприятиях напрямую в личные сообщения)
- `/unsubscribe` - Отписаться от уведомлений о новых событиях

### Административные команды
- `/statistics` - Просмотр статистики за прошлый месяц (только для администраторов)
- `/scheduler_status` - Проверка ежедневных анонсов и ежемесячной статистики (только для администраторов)
- `/weather_status` - Проверка статуса погодной системы (только для администраторов)

## Функциональность

### Основные возможности
- Создание и управление мероприятиями с точным временем начала
- Поиск мероприятий по различным временным периодам
- Присоединение к мероприятиям и отказ от участия
- Полное редактирование мероприятий (дата, время, место, трек, карта, описание)
- Автоматические ежедневные анонсы опубликованных событий на ближайшие 24 часа; функция включается отдельной настройкой
- Автоматическая ежемесячная статистика использования бота
- Публикация мероприятий в публичный канал с кнопками участия
- Система уведомлений участников об изменениях
- Ссылки на оригинальные сообщения о событиях в уведомлениях об изменениях
- Детальная статистика с анализом активности пользователей
- **Интеграция с прогнозом погоды**: если погодная функция включена, прогноз запрашивается при создании события, а после публикации запускаются автоматические обновления и уведомления о критичных изменениях; для черновиков фоновые погодные задачи не создаются
- **Надёжная доставка погодных уведомлений**: каждое сообщение или редактирование публикации хранится отдельно в PostgreSQL, повторяется с задержкой после временной ошибки Telegram и не отправляется заново уже успешным адресатам

### Типы мероприятий
- **Статические**: встречи, обсуждения, настольные игры - без дистанции и темпа
- **Активные**: велосипедные поездки, пробежки, активности на воде - с указанием дистанции, темпа, маршрута и карты

### Система уведомлений
- Уведомления участников при изменении деталей мероприятия
- Краткие уведомления в публичный канал со ссылками на оригинальные события
- Автоматический ежедневный анонс в канале содержит только опубликованные события, которые начнутся в ближайшие 24 часа; повторная отправка блокируется на 20 часов
- Погодные уведомления хранят состояние доставки в базе, повторяются до пяти раз и восстанавливаются после перезапуска
- После изменения даты, времени, координат или статуса публикации устаревшие погодные сообщения отменяются перед отправкой
- Перед повторной отправкой личного погодного уведомления бот проверяет, что получатель всё ещё является автором или участником события
- Если не удалось получить прогноз или подготовить сообщения, погодная задача повторяется до трёх раз с интервалом пять минут; после перезапуска восстанавливается этап, пропущенный менее часа назад
- В базе сохраняются число попыток, последняя ошибка и история ошибок по каждому адресату; удаление события каскадно удаляет связанную историю доставок
- `/weather_status` показывает ожидающие доставки, отдельно актуальные и устаревшие ошибки, ID затронутых событий и время самой ранней актуальной ошибки; служебный обработчик завершает уже подготовленные доставки даже при отключении новых погодных задач

После пяти неуспешных попыток доставка получает статус `failed` и требует внимания администратора. Уже успешно доставленные сообщения не отправляются повторно при обычной обработке. Однако если процесс аварийно завершится после принятия сообщения Telegram, но до записи успеха в PostgreSQL, повторная отправка возможна: Telegram API не предоставляет ключ, который полностью исключил бы это короткое окно.

Постоянная очередь сейчас используется только для погодных уведомлений. Ежедневный анонс отправляется напрямую несколькими сообщениями: если Telegram примет начало подборки, а затем вернёт ошибку, в канале может остаться неполный анонс. Надёжное продолжение такой частичной отправки требует отдельного переноса ежедневных анонсов в очередь доставок.

## Разработка

### Тесты

Unit-тесты не требуют запущенной базы данных:

```bash
bundle exec rspec spec/unit
```

Интеграционные тесты используют отдельную PostgreSQL-базу `velo_utro_bot_test` на порту `55432`:

```bash
docker compose -f compose.test.yml up -d --wait
bundle exec rspec spec/integration
docker compose -f compose.test.yml down
```

RSpec прекращает работу, если окружение отличается от `test` или имя базы не заканчивается на `_test`. Реальные HTTP-запросы во время тестов запрещены через WebMock. Интеграционный набор проверяет защиту очереди от дублей при конкурентной работе, повторные попытки, передачу просроченной блокировки новому обработчику, частичную доставку, смену версии события и завершение потерянной сверки. Откат связанных миграций разрешён только для пустой очереди и неиспользуемых версий; защитные проверки и безопасный цикл `down/up` тестируются отдельно. Отчёт покрытия создаётся локально в `coverage/`.

### Добавление новых команд

1. Создайте новый файл в директории `app/bot/commands/` с именем команды
2. Наследуйте класс от `Bot::CommandHandler` или `Bot::Handlers::InfoCommandHandler` для простой информационной команды
3. Реализуйте `execute` или `message_key` соответственно

**Пример информационной команды:**
```ruby
require_relative '../handlers/info_command_handler'

module Bot
  module Commands
    class MyCommand < Bot::Handlers::InfoCommandHandler
      private

      def message_key
        'my_command'
      end
    end
  end
end
```

### Добавление новых обработчиков callback-запросов

1. Создайте новый файл в директории `app/bot/callbacks/`
2. Наследуйте класс от `Bot::CallbackHandler` или `ParticipationHandler`
3. Реализуйте метод `process`

### Добавление новых обработчиков состояний

1. Создайте новый файл в директории `app/bot/states/`
2. Наследуйте класс от `Bot::StateHandler` или `EditHandler`
3. Реализуйте метод `process`
